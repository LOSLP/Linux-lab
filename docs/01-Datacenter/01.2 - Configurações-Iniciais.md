# Configurações Iniciais

## Objetivo

Realizar as configurações básicas do sistema operacional após a instalação.

## Configurações realizadas

### Criação de usuários 

Decidi criar dois usuários para o sistema. Um deles eu chamei de "voyager", o outro foi chamado de "octavio". O usuário chamado "voyager" foi criado com a intenção de ser um usuário comum padrão. Ele não possui nenhuma permissão, serve apenas como usuário de transição, para que a partir dele eu transite para o usuário "octavio", que será o usuário de uso do sistema, com permissão para virar root.

O motivo de eu ter feito dessa forma seria acrescentar uma camada extra de segurança. A ideia é que futuramente pretendo configurar o OpenSSH para bloquear login como root e permitir o login apenas por este usuário, somente via chave. Dessa forma, caso ele seja comprometido de alguma forma, o invasor teria ações limitadas no servidor. Ele teria que adivinhar a senha do usuário "octavio" para então poder virar root. Futuramente pretendo evoluir a configuração. 

### Hostname

O hostname do servidor foi definido como "sol".

Eu escolhi esse nome porque pretendo fazer uma organização baseada no sistema solar. O servidor principal recebe o nome "sol", enquanto os demais servidores utilizarão nomes de planetas.

### Atualização do sistema

Realizei as atualizações básicas do sistema, pôs instalação. 

### Personalização do bash dos usuários

Costumo sempre colocar uma personalização dentro do .bashrc dos meus usuários. Ela basicamente habilita cores no comando ls, para facilitar para mim a identificação de arquivos e diretórios, e faz com que o prompt do terminal mostre o usuário, o nome da máquina e o diretório atual em cores diferentes.

Também coloquei alguns aliases que facilitam meu uso no sistema no dia a dia. 

### Sincronização de data e hora

No RHEL e seus derivados vêm por padrão com o Chrony instalado. Hoje ele é a principal aplicação utilizada para sincronização de data e hora através do protocolo NTP.

Mesmo sabendo desse detalhe, eu escolhi fazer diferente. Preferi instalar a aplicação clássica ntpd para servir como referência de horário do meu servidor. O motivo dessa decisão se deve ao fato de que ainda existem empresas que utilizam sistemas legados que não suportam o Chrony. Além disso, achei interessante ver uma aplicação legado rodando em uma versão atual do sistema e validar seu funcionamento nesse cenário.

Para isso, tive que instalar um repositório chamado "epel-release". Ele é um repositório não padrão do RHEL e acrescenta a possibilidade de instalar diversos softwares à parte, entre eles o software "ntpsec", uma reimaginação atual do antigo aplicativo "ntpd", trazendo a possibilidade de utilizar essa aplicação em uma versão atual do sistema.

A configuração dele é praticamente idêntica à do NTP clássico. Acessei as configurações da aplicação e realizei o apontamento para os servidores do ntp.br, que são conhecidos e frequentemente utilizados pela comunidade Linux. A configuração funcionou perfeitamente após a inicialização do serviço.
