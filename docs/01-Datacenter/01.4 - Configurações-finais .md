## Configurações realizadas

### Instalação do Incus

O incus não estava disponível para instalação através dos repositórios oficiais do Rocky Linux, para realizar a instalação dele, se fez necessário habilitar o repositório CRB e adicionar e habilitar os pacotes do Incus hospedados no COPR. Somente então pude realizar a instalação. 

### Criação da Bridge 

O incus permite que através dele, seja criada uma interface bridge que será gerenciada por ele próprio, o que trás algumas facilidades, como dhcp e regras de firewall gerenciadas por ele, entre outras coisas, porem, eu optei por criar uma interface bridge manualmente e apontar o incus a ela. 

Escolhi dessa forma para aprender a fundo o funcionamento de uma bridge. Além disso, dessa forma o controle da bridge e do firewall ficam exclusivamente sobre minha responsabilidade, o Incus não tem controle nenhum sobre ambos, o que me da margem para ter um controle maior sobre o que esta sendo feito no sistema.

Defini o nome da Bridge como br-samba e ipv4 como 10.0.0.1/24, sendo assim a faixa dela ficou 10.10.10.0/24, dei esse nome pois pretendo vincular a ela um container contendo o samba 4. Inicialmente criei somente uma bridge, mas futuramente pretendo criar uma bridge para cada container, gerando assim um isolamento de rede, em que cada container pertence a uma rede diferente. 

### Criação do storage 

Utilizando o volume logico que dediquei ao incus, o montei em uma pasta no /srv e dei o nome da pasta de incus, entao criei uma pool  tambem chamada incus apontando para a pasta. Ela sera utilizada para hospedar os containers e seus arquivos.

### Criação do Primeiro Profile 

O incus me permite configurar um perfil de configuração, ao vincular esse perfil a um container, o container passara a utilizar as configurações que foram definidas no perfil. Inicialmente criei apenas um profile que será dedicado ao uso do container que ira hospedar o samba 4, por isso dei o nome do profile de samba-server.  

No perfil, defini as seguintes configurações:

- Inicio automático do container após boot do servidor
- Limite de 1 núcleo na CPU
- Limite de 1GiB de memoria 
- Limite de 200 processos ativos
- Isolamento de ID e GID nos containers
- Tipo de rede usada será Bridge
- A bridge usada sera a br-samba
- A placa de rede virtual sera uma NIC
- O espaço de disco dedicado será usado no /
- A pool usada será a Incus
- O tipo do armazenamento e disk

### Criação do Primeiro Container

Optei por utilizar containers de sistema na minha infraestrutura, escolhi o Debian trixie como SO do meu primeiro container. Vinculei o profile samba-server que criei a ele, então ele ira utilizar as configurações definidas no profile.

Ao iniciar o container o incus cria a placa de rede virtual, porem como não estou usando uma bridge gerenciada pelo próprio Incus, a placa de rede virtual que ele criou não pegou IP de forma automática com DHCP, sendo assim tive que inserir nela um ip de forma manual. Respeitando a faixa da bridge que criei, escolhi o IP 10.10.10.2/24.
