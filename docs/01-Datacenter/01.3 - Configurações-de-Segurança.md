# Configurações de Segurança 

## Objetivo

Realizar as configurações inicias de segurança do sistema. 

## Configurações realizadas

### Criação de Grupo

Realizei a criação do grupo "ssh-users" e atribui o usuário voyager a ele. O grupo será utilizado na configuração do ssh.

### Arquitetura do SSH  

#### Configuração do SSH

A aplicação Openssh foi instalada durante a instalação do servidor. Realizei algumas alterações nas configurações do SSH para reduzir o risco de invasões no sistema. 

Por padrão, na imagem escolhida para esse servidor, existe uma logica de `include` no arquivo de configuração do ssh, o "sshd_config", essa logica faz com que o sshd leia primeiro o conteúdo do diretório sshd_config.d, localizado em /etc/ssh. Dentro dele existia um arquivo padrão que incluía apenas uma única regra, permitir o login do root via ssh, optei por manter essa logica padrão de configuração do ssh, por considerar mais fácil de administrar as configurações do ssh, alterei o nome desse arquivo para "01-ssh.conf" e modifiquei as configurações do arquivo. 

Dentro do arquivo coloquei as seguintes regras:

- Bloqueio do login do root via ssh no servidor, habilitando somente o login do usuario voyager.
- Bloqueio de autenticação por senha, sendo possível realizar login somente via chave ssh.
- Habilitei o login via chave SSH no servidor.
- Defini o login via ssh sendo permitido apenas para os membros do grupo "ssh_users".
- Defini o numero máximo de tentativas de login via ssh como 3.
- Defini a porta do SSH como 22.

#### Configuração da Chave de Acesso

Realizei a criação de uma chave de autenticação ssh do tipo Ed25519 (255 bits), utilizando a ferramenta PuTTY Key Generator, armazenei a chave privada em um local seguro na minha estação de trabalho e armazenei a chave publica dentro do servidor. O armazenamento da chave foi feito da seguinte forma, eu realizei a criação de um diretório chamado Authorized_Keys, localizada dentro de /etc/ssh. Esse diretório, tem como objetivo armazenar todas as chaves publicas e privadas dos usuários que irão utilizar o servidor, dentro do diretório haverá um arquivo com o nome de cada usuário e dentro de cada arquivo será armazenado a chave individual dos usuarios.

A segurança dessa logica foi feita da seguinte forma, a pasta Authorized_Keys foi colocada como sendo propriedade do root e também do grupo root, as permissões da pasta foram colocadas como 755, os arquivos dentro dela com o nome dos usuários são atribuídos como propriedade do root o grupo é o grupo principal de cada usuário, a permissão dos arquivos é definida como 640. Essa logica foi pensada dessa forma para que os usuários não possam alterar ou apagar suas próprias keys de login e para facilitar a auditoria do servidor, uma vez que todas as keys de acesso estão dentro da mesma pasta sob controle exclusivo do root.

Essa pasta hospeda tanto chaves publicas como privadas, porque mesmo que o servidor principal "sol" só possa ser acessado com o usuário voyager, os demais servidores que ele irá hospedar, só poderão ser acessados através do servidor sol, então a pasta ira armazenar as chaves privadas de acesso aos demais servidores, neles haverá a mesma pasta, com a chave publica armazenada. 

No meu nível de conhecimento atual, essa foi a melhor solução de segurança que pude desenvolver para restrição de chaves ssh, pensei em fazer dessa forma, pois os usuários em bora tenham acesso a esta basta como leitores e possam ver os arquivos dentro dela, não são capazes de alterar a pasta e nem os arquivos, cada usuário pode ver sua própria chave key, mas não pode ver a chave dos demais usuários somente a sua. Sendo assim, caso o usuário voyager seja comprometido de alguma forma, o invasor poderia adentrar na pasta e ver os demais usuários, mas não teria qualquer ação dentro da pasta, sendo possível ver apenas a chave key publica do usuário voyager e nao a dos demais usuários.
