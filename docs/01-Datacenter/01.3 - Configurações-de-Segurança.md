# Configurações de Segurança 

## Objetivo

Realizar as configurações inicias de segurança do sistema. 

## Configurações realizadas

### Arquitetura do SSH  

#### Configuração do SSH

Por padrão, a aplicação Openssh foi instalada durante a instalação do servidor. Realizei algumas alterações nas configurações do SSH para reduzir o risco de invasões no sistema. 

Como medida de segurança, realizei o bloqueio do login do root via ssh no servidor, habilitando somente o login do usuario voyager. 

#### Configuração da Chave de Acesso

Realizei a criação de uma chave de autenticação ssh do tipo Ed25519 (255 bits), utilizando a ferramenta PuTTY Key Generator, armazenei a chave privada em um local seguro na minha estação de trabalho e armazenei a chave publica dentro do servidor. O armazenamento da chave foi feito da seguinte forma, eu realizei a criação de uma pasta chamada Authorized_Keys, localizada dentro de /etc/ssh. Essa pasta, tem como objetivo armazenar todas as chaves publicas e privadas dos usuários que irão utilizar o servidor, dentro da pasta haverá um arquivo com o nome do usuário e dentro dele será armazenado a chave. 

A segurança dessa logica foi feita da seguinte forma, a pasta Authorized_Keys foi colocada como sendo propriedade do root e também do grupo root, as permissões da pasta foram colocadas como 755, os arquivos dentro dela com o nome dos usuários são atribuídos como propriedade do root e com o grupo será o grupo principal de cada usuário, a permissão dos arquivos é definida como 640. Essa logica foi pensada dessa forma para que os usuários não possam alterar ou apagar suas próprias keys de login e para facilitar a auditoria do servidor, uma vez que todas as keys de acesso estão dentro da mesma pasta sob controle exclusivo do root. 

Essa pasta hospeda tanto chaves publicas como privadas, porque mesmo que o servidor principal "sol" só possa ser acessado com o usuário voyager, os demais servidores que ele irá hospedar, só poderão ser acessados através do servidor sol, então a pasta ira armazenar as chaves privadas de acesso aos demais servidores, neles haverá a mesma pasta, com a chave publica armazenada. 

No meu nível de conhecimento atual, essa foi a melhor solução de segurança que pude desenvolver para restrição de chaves ssh, pensei em fazer dessa forma, pois os usuários em bora tenham acesso a esta basta como leitores e possam ver os arquivos dentro dela, não são capazes de alterar a pasta e nem os arquivos, cada usuário pode ver sua própria chave key, mas não pode ver a chave dos demais usuários somente a sua. Sendo assim, caso o usuário voyager seja comprometido de alguma forma, o invasor poderia adentrar na pasta e ver os demais usuários, mas não teria qualquer ação dentro da pasta, sendo possível ver apenas a chave key publica do usuário voyager e nao a dos demais usuários.
